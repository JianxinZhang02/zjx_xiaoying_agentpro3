# 实现复盘

记录本次实际观察，不代替候选人个人学习心得。

## 最难的问题

模型接入要分别验证地址、工作空间权限和模型 ID。原环境密钥返回 403；用户提供新密钥后访问成功，但原模型名返回 404。确认最终模型后才验证了工具选择和结果回传；不能用普通对话可用替代 Agent 链路验证。

回答范围与冲突边界同样重要。首轮发现了真实的期限冲突，却将其带入只问材料的任务，自动验收仅 10/12。另有“临时按更严格期限”和无依据 HR 系统建议。引用真实不等于整个回答恰当，必须核对当前任务和每项业务主张。

证据还需区分预期、Mock、真实运行、自动检查与 AI 语义复核，保留失败，不能只展示顺利路径。

## 实际改进

1. 先运行真实工具协议探针，分层记录错误。
2. 增加本轮事项范围约束，避免无关冲突阻断。
3. 禁止用保守建议选择冲突制度，禁止补造企业系统和流程。
4. 校验本次成功读取的原文，持续失败时不转述未核实业务数字。
5. 用数字变更、增删冲突资料和工具故障验证下一步动作。

## 限制与下一步

- 小语料和一次最终 live 矩阵不能估计生产可靠率；增加独立改写集、多次重复运行。
- BM25 依赖词面重合；先评估召回缺口，再决定同义词、向量检索或重排。
- 引用匹配不证明语义支持或穷尽冲突；建立句子到证据标注集。
- 历史由调用方显式输入，没有会话服务和长期记忆；CLI 与可审查证据优先。
- 没有大规模注入攻击评估、租户隔离或生产部署，只交付本地考核 MVP。
