# 实现复盘与下一步

本记录是实际工具执行与 AI 复核记录，不代替候选人个人学习心得。

## 难点与修改

1. 接入地址、空间权限和模型 ID 分别验证：早期 403、404 都保留，用户确认凭证与模型后完成真实协议探针。
2. 有引用不等于回答范围恰当：原生版和首轮图版本都暴露过未问期限被加入材料回答。改进通用提示词和结束参数描述，没有硬编码用例答案。
3. 框架名称不能证明 ReAct：迁移后进一步记录每次实际观察如何被后续模型收到；同轮多个工具不伪装为观察后的重规划。
4. 运行状态要有单一来源：消息、成功证据和计数进入 AgentState，节点由 LangGraph 调度；不是把旧 while 套一层。
5. 额度不同：模型调用、工具调用和图节点步数分别计数，避免把框架递归步数误当模型请求次数。三类上限都有明确未完成处理。

首轮 LangGraph 12/14，包括一次超时和一次内容范围失败；修正后完整矩阵 14/14。所有失败仍保留，可复查原因。一次最终矩阵不代表长期稳定准确率。

## 当前限制

十篇合成制度、词面检索、人工预定义片段；没有上传解析、大规模知识库或正式企业系统。引用匹配不证明回答所有语义，模型可能遗漏未召回的制度。
InMemorySaver 只用于运行内检查，未实现跨进程持久化、从检查点续跑或用户确认后恢复。没有界面、部署、租户隔离与生产安全保证。

## 下一步

先增加独立问法、隐藏冲突及重复运行的评估；定位召回与证据判断问题，再决定同义词/向量检索/重排。
若加入用户确认后继续任务，配置持久化 checkpointer 和 interrupt/resume，并测试恢复及重复执行。当前不把框架具备的能力写成已实现功能。
