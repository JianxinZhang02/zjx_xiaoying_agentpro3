# 需求与成功标准

## 用户与目标

员工使用 CLI 询问企业制度；运营或评审可以核对检索、读取、冲突处理和失败状态。
所有制度为合成数据，不能用作实际企业制度或法律建议。

## MVP 范围

本地 JSON 制度、BM25 检索、原文读取、原生模型工具调用、结构化回答、引用校验、对话历史、执行上限、真实与离线模式。
不包含网页、部署、向量库、多 Agent 和真实企业系统接入。

## 验收

1. 明确答案：回答由本次读取的原文支持。
2. 文档冲突：30 天与 15 天且无优先级，查证后列出冲突并请求确认。
3. 资料外问题：说明缺口，不补造事实。
4. 改写问题：口语化表达仍能发现相关证据。
5. 上下文追问：承接前文主题并查阅原文。
6. 工具失败：错误交回模型，保留成功结果，调整或明确未完成。

默认最多 8 次模型调用、10 次工具调用、单次请求超时 60 秒；达到上限明确未完成。
最终状态为 answered、needs_clarification、insufficient_evidence 或 incomplete。
版本日期不自动构成制度优先级。Mock 只证明流程，不证明真实模型效果。
